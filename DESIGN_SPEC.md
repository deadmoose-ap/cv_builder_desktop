# CV Builder — Calm Workspace redesign

## 1. Цель

Перевести CV Builder из набора системных форм в лёгкое, сфокусированное рабочее
пространство. Новый интерфейс должен:

- ясно показывать структуру CV и текущий раздел;
- помогать последовательно заполнить документ;
- уменьшить визуальный шум и длину перемещений взгляда;
- сохранять локальную/offline-модель приложения;
- масштабироваться на новые разделы без перестройки главного окна;
- одинаково работать на macOS и Windows на базе `CustomTkinter`.

Редизайн не меняет формат JSON, структуру данных и результат PDF-генерации.

## 2. Проблемы исходного интерфейса

1. Верхние вкладки выглядят как системный контрол и не передают прогресс.
2. Все файловые команды имеют одинаковый визуальный вес.
3. Поля растягиваются почти на всю ширину окна, а подписи слева увеличивают
   расстояние сканирования.
4. На экранах остаются большие неструктурированные пустые области.
5. Experience представлен списком строк, а действия отделены от выбранной записи.
6. Редактирование Experience открывает высокий модальный диалог и разрывает
   контекст основного сценария.
7. Статус `Ready` не даёт пользователю полезной информации.

## 3. Выбранная концепция

**Calm Workspace**:

- компактный header с брендом, состоянием файла и основными командами;
- постоянная левая навигация по разделам;
- индикатор заполнения CV;
- центральная контентная область с ограниченной визуальной шириной;
- карточки для логически связанных данных;
- встроенный редактор Experience вместо отдельного окна;
- один основной CTA на экран.

Опциональная панель предпросмотра PDF из концепции CV Studio может быть добавлена
позже, не меняя архитектуру навигации.

## 4. Информационная архитектура

```text
Application
├── Header
│   ├── Product identity
│   ├── Document/autosave status
│   ├── All CVs
│   ├── Export JSON
│   └── Export PDF — primary
└── Workspace
    ├── Sidebar
    │   ├── Completion
    │   ├── Profile
    │   ├── Summary
    │   ├── Experience
    │   └── Education
    └── Content
        ├── Section heading
        ├── Section-specific content
        └── Contextual action
```

## 5. Дизайн-система

### 5.1 Цветовые токены

| Token | Value | Use |
|---|---:|---|
| `background` | `#F6F7FB` | фон рабочего пространства |
| `surface` | `#FFFFFF` | header, карточки, поля |
| `surface_alt` | `#EFF3F8` | sidebar и мягкие состояния |
| `text` | `#172033` | основной текст |
| `muted` | `#667085` | пояснения и метаданные |
| `border` | `#D7DDE8` | разделители и границы |
| `accent` | `#2F6BFF` | основной CTA и фокус |
| `accent_hover` | `#2457D6` | hover/pressed |
| `selection` | `#EAF0FF` | активный раздел |
| `danger` | `#B42318` | удаление |
| `success` | `#127A45` | подтверждённое сохранение |

Все цвета задаются явно через общие токены. `CustomTkinter` обеспечивает
предсказуемые скруглённые поверхности и контролы на macOS и Windows.

### 5.2 Типографика

- системный шрифт Tk;
- заголовок экрана: 22 px, bold;
- заголовок карточки: 14–15 px, bold;
- основной текст: системный размер;
- вторичный текст: системный размер, цвет `muted`;
- подписи полей располагаются над полями.

### 5.3 Геометрия

- базовый шаг: 4 px;
- стандартные интервалы: 8, 12, 16, 24, 32 px;
- header: около 60 px;
- sidebar: 210–220 px;
- внутренний padding контента: 28–36 px;
- padding карточки: 20–22 px;
- минимальная высота поля: около 38 px;
- минимальное окно: 900 × 660;
- целевое окно: 1120 × 780.

### 5.4 Компоненты

- `Primary button`: только Export PDF и основной контекстный CTA;
- `Secondary button`: Save, Cancel, переходы;
- `Ghost button`: New/Open и низкоприоритетные действия;
- `Navigation item`: номер раздела + название, активное состояние `selection`;
- `Card`: белая поверхность, тонкая граница, внутренний отступ;
- `Form field`: подпись сверху, поле снизу, видимый focus accent;
- `Experience card`: роль, компания, период/место и локальные действия;
- `Progress`: процент заполнения обязательных частей CV.

## 6. Спецификация экранов

### Profile

- заголовок и краткая подсказка;
- одна карточка формы;
- Full name и Headline занимают всю строку;
- Location и Email объединены в двухколоночную строку;
- LinkedIn/website занимает всю строку;
- Core skills — многострочное поле с пояснением.

### Summary

- одна сфокусированная карточка;
- текстовое поле заполняет доступную высоту;
- инструкция о пустой строке вынесена в подзаголовок;
- счётчик символов обновляется во время ввода.

### Experience

- записи представлены отдельными карточками;
- Add role находится в заголовке раздела;
- Edit, reorder и Delete находятся рядом с соответствующей записью;
- Add/Edit открывают встроенный редактор внутри раздела;
- редактор сохраняет запись только после `Save entry`;
- `Cancel` возвращает список без изменений;
- удаление требует подтверждения;
- пустое состояние объясняет следующий шаг.

### Education

- одна карточка с Institution и Qualification/dates;
- структура допускает переход к списку нескольких записей в будущей версии.

## 7. Состояния и обратная связь

- header показывает `Untitled CV`, имя открытого файла, `Unsaved changes`,
  результат сохранения или генерации;
- прогресс считается по заполненности Profile, Summary, Experience и Education;
- ошибки открытия, сохранения и генерации остаются системными диалогами;
- обязательные поля Experience: Company и Role;
- клавиши `Cmd/Ctrl+S` сохраняют документ;
- `Escape` закрывает встроенный редактор Experience без сохранения.

## 8. Техническая спецификация

### 8.1 Архитектура UI

- визуальный слой реализовать на `CustomTkinter 5.2+`, сохранив стандартный
  Tk event loop и файловые диалоги;
- заменить `ttk.Notebook` на `content_host` с несколькими `CTkFrame`;
- переключать разделы через `tkraise`;
- хранить кнопки sidebar в словаре и менять их цвет/типографику при навигации;
- сохранить `collect_form`, `populate_form`, файловые операции и PDF-генератор;
- Experience editor реализовать как второй frame внутри Experience section;
- карточки Experience пересоздавать из `self.data["experience"]`;
- текстовые поля оформлять единым helper-методом;
- использовать `AutoHideScrollableFrame`: scrollbar скрыт, когда контент
  помещается, и появляется только при реальной необходимости;
- закрепить действия `Cancel` и `Save entry` вне прокручиваемой части editor;
- не использовать системные `LabelFrame` и постоянные рамки вложенных групп.

### 8.2 Два этапа исправления визуального соответствия

**Этап 1 — компоновка и поведение:**

- убрать вложенные системные рамки и чёрные границы многострочных полей;
- ограничить размеры кнопок по их роли;
- исправить перенос текста privacy footer;
- скрывать неактуальные scrollbar;
- закрепить footer встроенного Experience editor.

**Этап 2 — визуальная система:**

- перенести карточки, поля, кнопки, навигацию и progress на `CustomTkinter`;
- применить радиусы 8–13 px и токены Calm Workspace;
- сохранить иерархию primary/secondary/ghost/danger;
- проверять результат по PNG-захватам реального окна, а не только по
  HTML-макетам.

### 8.3 Совместимость данных

Сохраняются существующие ключи:

```text
profile: name, headline, location, email, linkedin, skills, summary
experience[]: company, duration, role, dates, place, intro, work, results
education: institution, qualification
```

Миграция существующих `.json` не требуется.

### 8.4 Расчёт прогресса

Десять равновесных признаков:

1. name;
2. headline;
3. location;
4. email;
5. linkedin;
6. хотя бы один skill;
7. summary;
8. хотя бы одна experience entry;
9. education institution;
10. education qualification.

Процент округляется до целого. Расчёт вынесен в чистую функцию и покрывается
тестом. Новый документ содержит пустые значения. Instructional placeholders
существуют только в UI, исчезают при фокусе и никогда не попадают в JSON,
progress или PDF.

### 8.5 Локальная библиотека и autosave

- стартовый экран показывает все локальные CV, дату изменения и прогресс;
- каждый CV хранится как обычный JSON в системной writable-директории
  приложения (`Application Support` на macOS);
- `library.json` содержит только id, пользовательское название и timestamps;
- изменение формы сохраняется автоматически с debounce 650 мс;
- запись выполняется атомарно через временный файл и rename;
- переход в `All CVs` и закрытие приложения завершают pending save;
- пользователь может создавать, открывать, переименовывать и удалять CV;
- удаление требует подтверждения и рекомендует предварительный JSON export.

### 8.6 Обмен JSON

- `Example JSON` сохраняет заполненный пример неизменившейся схемы;
- `Import JSON` валидирует файл, создаёт отдельный CV в библиотеке и сразу
  открывает его;
- `Export JSON` сохраняет переносимую копию текущего CV;
- импорт старых JSON остаётся совместимым благодаря нормализации отсутствующих
  необязательных полей.

## 9. План реализации

1. Ввести дизайн-токены и `CustomTkinter`.
2. Перестроить root layout на header/sidebar/content host.
3. Реализовать навигацию и индикатор заполнения.
4. Перенести Profile, Summary и Education в карточные формы.
5. Перестроить Experience в карточный список.
6. Заменить Experience modal на встроенный editor state.
7. Подключить dirty/status feedback и горячие клавиши.
8. Разделить HTML-референсы (`ui-reference`) и захваты приложения
   (`ui-screens`).
9. Добавить тесты pure UI helpers и прогнать полный test suite.
10. Снять новые референсные экраны и проверить компоновку визуально.
11. Добавить стартовую библиотеку CV и системное внутреннее хранилище.
12. Подключить debounce autosave и атомарную запись JSON.
13. Отделить UI placeholders от пустой модели документа.
14. Добавить Example JSON, Import JSON и Export JSON.

## 10. Критерии приёмки

- все четыре раздела доступны из постоянной навигации;
- активный раздел визуально различим;
- существующие JSON импортируются в локальную библиотеку;
- несколько CV доступны на отдельном стартовом экране;
- изменения формы автоматически сохраняются в фоне;
- placeholders исчезают при фокусе и не считаются данными;
- пример JSON экспортируется, а отредактированный JSON импортируется и
  открывается автоматически;
- PDF генерируется тем же модулем;
- Experience добавляется, редактируется, удаляется и меняет порядок;
- редактирование Experience не создаёт отдельное окно;
- progress и summary character count обновляются;
- приложение помещается в минимальное окно без наложения контролов;
- неактуальные scrollbar отсутствуют, а действия редактора всегда доступны;
- карточки, поля и кнопки имеют скругления из дизайн-системы;
- smoke tests проходят;
- новые скриншоты демонстрируют библиотеку, Profile, Summary, Experience,
  Education и встроенный Experience editor.

## 11. Иконка приложения

Иконка использует концепцию **Glass Ribbon**: светлый CV-документ переходит в
синюю восходящую ленту. Для устранения размытия используется optical sizing:

- `512–1024 px` — полный Liquid Glass raster с объёмом и рефракциями;
- `64–256 px` — controlled Liquid Glass: упрощённый документ, крупные
  CV-детали, двойная стеклянная кромка и объёмная лента;
- `32 px` — компактный CV с портретом и строками, одной системой бликов и
  усиленной сине-фиолетовой лентой;
- `16 px` — отдельный master с двумя контрастными силуэтами и минимальным
  стеклянным rim-light.

Каждый размер рендерится из ближайшего master, а не уменьшается из одного
1024px PNG. Исходники находятся в `assets/icon-concepts`, готовый macOS iconset
— в `assets/CVBuilder.iconset`, bundle-ресурс — `assets/CVBuilder.icns`.
